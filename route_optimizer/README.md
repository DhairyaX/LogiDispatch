# Logistics Route Optimization Platform Backend

This directory contains the Python-based backend for the Logistics Platform. It is divided into two primary domains:

1. **`api/`**: A modern, production-ready FastAPI web service that exposes the platform's capabilities via REST endpoints.
2. **`optimization/`**: The heavy-lifting mathematical engine that uses Google OR-Tools to solve Vehicle Routing Problems (VRP).

## Architecture

The system uses a layered architecture designed for easy transition to MongoDB:

```text
React Frontend  ─▶  FastAPI Routers  ─▶  API Services  ─▶  OR-Tools Engine
                                               │
                                               ▼
                                      (In-Memory Mock DB)
                                      (Future: MongoDB)
```

## Running the Server

To run the backend server with hot-reloading for development:

```bash
# Make sure you are in the project root directory (parent of route_optimizer)
uvicorn route_optimizer.api.main:app --reload
```

- The server runs on `http://127.0.0.1:8000`
- The interactive Swagger API Documentation is at `http://127.0.0.1:8000/docs`

## API Endpoints

| Domain | Method | Endpoint | Description |
|--------|--------|----------|-------------|
| Health | GET | `/api/v1/health/` | Health check endpoint |
| Drivers | GET, POST, PUT, DELETE | `/api/v1/drivers/` | CRUD for Drivers |
| Vehicles | GET, POST, PUT, DELETE | `/api/v1/vehicles/` | CRUD for Vehicles |
| Deliveries | GET, POST, PUT, DELETE | `/api/v1/deliveries/` | CRUD for Delivery locations |

## Frontend Integration Guide

The FastAPI backend is fully configured with CORS middleware allowing connections from `http://localhost:5173`. 
To integrate the frontend, replace the in-memory Zustand actions (in `logisticsStore.ts`) with asynchronous `fetch` calls to `http://localhost:8000/api/v1/...`.

## Future MongoDB Integration Plan

The application uses Dependency Injection (`route_optimizer/api/dependencies/services.py`). 
To switch from the current in-memory storage to MongoDB:
1. Create MongoDB repositories using `motor` (async MongoDB driver).
2. Update the implementations inside the classes in `route_optimizer/api/services/`.
3. No changes to routers, schemas, or the frontend will be necessary.

## MongoDB Atlas Setup

The FastAPI backend uses MongoDB Atlas for data persistence.

### Environment Variables
Ensure your .env file contains the following keys:
`
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster-url>/?appName=logistics-cluster
MONGODB_DB_NAME=logistics_db
`

### Connection Testing
You can verify the connection to MongoDB Atlas by running the provided standalone test script:
`ash
python test_mongo.py
`
This script will load the credentials from .env, attempt a ping command against the Atlas cluster, and list the available collections in your logistics_db.

### Troubleshooting
- **Connection Refused / Network Access Denied**: Ensure your current IP address is allowlisted in the MongoDB Atlas Network Access panel.
- **Authentication Failed**: Verify that your MONGODB_URI contains the correct database user credentials.

### Repository Architecture & CRUD Flow
The application has fully migrated to a Repository Pattern to interact with MongoDB. This completely eliminates any in-memory or temporary dictionaries.

**Flow:**
`React Frontend` ➔ `FastAPI Router` ➔ `Service Layer` ➔ `MongoDB Repository` ➔ `Atlas Cluster`

**Collections:**
- `drivers`: Stores active fleet personnel. (`DriverRepository`)
- `vehicles`: Stores fleet vehicles and their statuses. (`VehicleRepository`)
- `deliveries`: Stores pending and assigned delivery locations. (`DeliveryRepository`)
- `routes`: Stores historical route optimization outputs generated by the OR-Tools engine. (`RouteRepository`)
- `analytics`: Stores calculation snapshots detailing workload balance and fleet utilization. (`AnalyticsRepository`)

**Object ID Handling:**
The backend schemas automatically map MongoDB's internal `ObjectId` (`_id`) to a string representation (`id`) before sending data to the frontend, ensuring compatibility with REST standards. During route optimization, temporary sequential integer IDs are dynamically generated to satisfy the legacy OR-Tools engine, and perfectly re-mapped to their Atlas string IDs before the final response is built.
